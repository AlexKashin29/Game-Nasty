# Ты — моя вселенная

**«Письмо через вселенную» — одно цельное приключение для Насти от Саши.**

Настя и кот идут по звёздным дорожкам, собирают рассыпавшееся письмо Саши и открывают следующую главу. В приложении есть единая игра, маршрут, альбом находок, письмо и настройки. Шесть глав меняют историю и лабиринт, но не правила и управление.

## Как играть

- Идите на соседнюю клетку нажатием, свайпом, стрелками или WASD (работают также ЦФЫВ).
- Меняйте солнечный и лунный свет кнопкой под картой; с клавиатуры — пробелом, когда карта в фокусе. Золотые мосты доступны при солнце, серебряные — при луне.
- В каждой главе найдите три искры и ключ. Затем войдите в круглый портал.
- Сердечко — необязательный тайник с личной запиской.
- Кнопка «Кот, покажи дорогу» подсвечивает следующий шаг к необходимой находке либо предлагает сменить свет. Она не проходит игру автоматически.
- После портала открывается следующая страница и кнопка продолжения. В конце все страницы складываются в признание.

Таймера, жизней и наказаний за ошибки нет. Можно спокойно исследовать развилки. Сохраняются позиция, свет, ключ, находки и главы. Альбом и письмо доступны через навигацию, игра продолжается с того же места. Сброс требует отдельного подтверждения.

## Файлы

- `index.html` — оболочка приложения и навигация.
- `styles.css` — адаптивная вёрстка, игровая карта и анимации.
- `script.js` — **один** движок приключения, сохранение и экраны приложения.
- `data.json` — все шесть сценариев, карты, комплименты, секреты, финал и пути к изображениям.
- `assets/` — пользовательские изображения, извлечённые из предоставленного архива, а также ранее созданные SVG. Исходный архив, HTML и PNG пользователя сохранены без изменений.
- `sw.js` — офлайн-кэш после первого успешного онлайн-посещения.
- `manifest.webmanifest` — метаданные для добавления приложения на главный экран поддерживающего браузера. Установка необязательна.
- `.github/workflows/pages.yml` — проверка и автоматическая публикация на GitHub Pages после изменений в `main`.
- `tests/validate.cjs` — проверка структуры, файлов и проходимости всех сценариев.
- `tests/browser.cjs` — реальное сквозное прохождение и проверки интерфейса через Playwright.

## Локальная разработка

Для сайта не нужны сборка, Node-зависимости или аккаунт. Для локальной разработки запустите HTTP-сервер из этой папки:

```sh
python3 -m http.server 8000
```

Открывайте приложение через сервер: `fetch` JSON и service worker не работают при простом открытии HTML через `file://`. В опубликованной версии достаточно открыть сайт в браузере.

## GitHub Pages

Рабочий процесс в `.github/workflows/pages.yml` запускается при push в `main` или вручную через **Actions → Publish Nastya's universe → Run workflow**. Он проверяет сценарии, собирает только файлы сайта в артефакт и публикует его. Исходные архивы и тесты не включаются в артефакт Pages.

GitHub Pages должен быть включён для репозитория с источником **GitHub Actions** (Settings → Pages → Source). Первичное включение Pages требует административного API-доступа либо изменения этой настройки владельцем; обычный `GITHUB_TOKEN` workflow не может сам включить Pages в новом репозитории.

Ожидаемый адрес после успешной публикации: `https://alexkashin29.github.io/Game-Nasty/`. Наличие workflow и push не доказывают, что публикация завершилась: результат подтверждается успешным `Publish` и HTTP-проверкой сайта.

Все ссылки, manifest и service worker используют относительные пути и поддерживают подпапку `/Game-Nasty/`.

## Как менять историю

В `data.json` массив `chapters` содержит шесть глав. Поля:

- `id`, `title`, `theme`, `color` — идентификатор, заголовок и атмосфера.
- `intro`, `ending`, `fragment`, `achievement`, `secret` — сюжетные тексты и награды.
- `grid` — семь строк по семь символов: `#` — пустота, `.` — дорожка, `s` — солнечный мост, `m` — лунный.
- `start`, `exit`, `key`, `cache` — индексы клеток от 0 до 48, слева направо и сверху вниз.
- `stars` — ровно три объекта с `at` (индекс клетки) и `text` (комплимент).
- `photo` — относительный путь к изображению, открываемому в альбоме.

Все объекты должны находиться на разных обычных дорожках, а главы — иметь уникальные `id`. После изменений карты запустите `node tests/validate.cjs`: он перебирает состояние карты со светом, всеми искрами, ключом и тайником, подтверждая проходимость.

`characters` задаёт изображения Насти, Саши, кота, пары и финала. `finale` задаёт признание и галактику комплиментов. Персональные изображения используются из файлов, уже загруженных пользователем в репозиторий; они не генерируются заново и не отправляются сторонним сервисам.

## Проверки

Без установки зависимостей:

```sh
node --check script.js
node --check sw.js
node tests/validate.cjs
git diff --check
```

Для необязательной браузерной проверки нужен Playwright и Chromium. Пример установки тестового инструмента отдельно от проекта:

```sh
npm install --prefix /tmp/nastya-tests --cache /tmp/npm-cache playwright
NODE_PATH=/tmp/nastya-tests/node_modules node tests/browser.cjs
```

Тест ожидает запущенный HTTP-сервер на порту 8000 и Chromium по пути `/usr/bin/chromium`. Переопределения: `TEST_URL` и `CHROMIUM_PATH`. Он использует новый профиль браузера, не трогая личные сохранения. Проверяются все главы, свет, секреты, финал, альбом, клавиатура, восстановление, сброс, звук, ширины 320/375 пикселей, офлайн-режим, недоступное хранилище и ошибка загрузки контента.

## Сохранение и обновления

Ключ сохранения — `nastya-letter-adventure-v2`. Достижения прежних версий импортируются в альбом как памятные награды; они не пропускают главы новой истории. Старые сохранения не удаляются. Прогресс привязан к браузеру и домену, между устройствами не синхронизируется. Если хранилище заблокировано, игра работает в памяти и сообщает об этом.

Service worker сохраняет основные ресурсы после первого успешного посещения, чтобы приложение открывалось без сети. При подключении используются свежие сетевые ресурсы. При изменениях состава кэша повышайте версию `CACHE` в `sw.js`. Кэш нового service worker активируется после закрытия прежних вкладок; при обновлении учитывайте совместимость старых сохранений.

Звуки синтезируются Web Audio и выключены по умолчанию. Внешних шрифтов, аналитики и сторонних CDN у приложения нет. Анимации учитывают `prefers-reduced-motion`. Секретный финал — часть истории, а не криптографическая защита: ответы и тексты статического сайта доступны в JSON.
